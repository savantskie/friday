ISSUE RESOLVED
--------------
Retroactive migration was creating 80 conversation files (4 correct + 75 malformed)
instead of properly grouping into monthly files.

ROOT CAUSE
----------
The _group_records_by_target_db() method used unsafe pattern matching:

    OLD CODE (BUGGY):
    for field in record:
        if isinstance(field, str) and "T" in str(field) and "-" in str(field):
            timestamp_str = str(field)
            break

When conversation content contained "T" and "-" characters (e.g., "That's-real",
"I'm-sorry"), the code mistakenly treated it as an ISO timestamp, creating files
like: conversations_"Fuck,".db, conversations_I'm sor.db, etc.

SOLUTION
--------
Three-part fix using sqlite3.Row factory for safe named column access:

1. ENABLE ROW FACTORY (line 473)
   source_conn.row_factory = sqlite3.Row
   
2. USE NAMED COLUMN ACCESS (lines 596-630)
   NEW CODE (FIXED):
   timestamp_col = self._get_timestamp_column(db_type)
   timestamp_str = record[timestamp_col]  # Access by name, not pattern matching
   
3. CONVERT ROW TO TUPLE FOR INSERTION (lines 639-688)
   record_tuples.append(tuple(record))  # Preserve for INSERT statement

TIMESTAMP COLUMN MAPPING
------------------------
The existing _get_timestamp_column() method defines:
  - conversations → "timestamp"
  - ai_memories → "timestamp_created"
  - schedule → "timestamp_created"
  - mcp_tool_calls → "timestamp"
  - vscode_project → "timestamp"
