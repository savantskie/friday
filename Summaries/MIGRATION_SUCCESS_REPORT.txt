================================================================================
THE UNIX TIMESTAMP MYSTERY
================================================================================

Those old conversation files (1762007, 1762008, etc.) have timestamps like:
  1762007310  (Unix epoch seconds)

Instead of modern ISO format like:
  2025-08-05T10:30:00Z

The migration logic couldn't group them by date because the timestamp format
is fundamentally different. BUT THIS IS COMPLETELY FINE because:

1. File discovery doesn't depend on the filename format
   → They're found via: conversations_*.db glob pattern

2. Queries don't depend on timestamp structure
   → They retrieve all messages from the file anyway

3. Semantic search doesn't care about timestamps
   → It searches by content, not date
