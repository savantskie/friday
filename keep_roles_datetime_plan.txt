Plan: Dynamic Context Preservation via message_spans + New datetime Role

GOALS

1. Give the main chat model (Gemma4) awareness of current time without modifying the system prompt
2. Dynamically preserve system + identity tokens during context shift by replacing the flat --keep flag with a message_spans-based calculation
3. --keep CLI flag becomes unnecessary

INVESTIGATION SUMMARY: ROLE-AWARE KV CACHE

The core idea is to replace the flat --keep N flag (which preserves N raw tokens from the start) with a role-aware mechanism that pinpoints exact message boundaries. This uses llama.cpp's existing message_spans system (common/chat.h:157-191), which scans the rendered token stream for delimiter sequences and maps token positions to roles.

What was found:
- Our custom Jinja template bypasses the autoparser entirely -- it's intercepted by the Gemma4 specialized handler at chat.cpp:2990-2998, which hardcodes only user and assistant delimiters
- System and all custom roles (identity, summary, reminders, memories) are lumped into UNKNOWN spans
- The fix: add delimiters for system and identity to common_chat_params_init_gemma4 at chat.cpp:1294
- The split() function at chat.cpp:152 does exact token-sequence matching -- each span cleanly covers from one role's delimiter to the next, giving precise role-level boundaries
- A new --keep-roles flag (e.g., --keep-roles system,identity) allows specifying which roles to preserve dynamically, without hardcoding role names in the C++ code

Key behaviors:
- --keep-roles system,identity pins through end of identity span (system + identity tokens preserved, everything else shiftable)
- --keep-roles system pins only system tokens (identity + everything else shiftable)
- --keep-roles not specified falls back to existing --keep N behavior
- If --keep-roles is specified but no spans match, loud warning to log + keep_roles_error.log, full-context fallback

4d. Dynamic n_keep calculation in context shift

File: tools/server/server-context.cpp, pre_decode() (line ~2862)

Replace the current flat n_keep line with logic that checks --keep-roles first, falls back to --keep:

// Calculate n_keep from message_spans if --keep-roles is specified
int n_keep;
const auto & keep_roles = slot.task->params.keep_roles;
if (!keep_roles.empty()) {
    // Build a set of common_chat_role values to match
    std::set<common_chat_role> keep_role_set;
    for (const auto & role_name : keep_roles) {
        keep_role_set.insert(common_chat_role_from_string(role_name));
    }
    // Find the end of the last span matching any keep role
    const auto & spans = slot.task->params.message_spans;
    size_t keep_end = 0;
    for (const auto & span : spans.spans) {
        if (keep_role_set.count(span.role)) {
            keep_end = std::max(keep_end, span.pos + span.len);
        }
    }
    if (keep_end > 0) {
        n_keep = (int)keep_end;
    } else {
        // Span detection failed -- log warning, do NOT silently fall back to --keep
        std::string roles_str;
        for (size_t i = 0; i < keep_roles.size(); i++) {
            if (i > 0) roles_str += ",";
            roles_str += keep_roles[i];
        }
        std::string spans_str;
        for (const auto & s : spans.spans) {
            if (!spans_str.empty()) spans_str += "; ";
            spans_str += common_chat_role_to_string(s.role) + "@" + std::to_string(s.pos) + "+" + std::to_string(s.len);
        }
        int turn_num = slot.n_past;
        std::string warn_msg = "keep_roles detection failed: roles=" + roles_str
            + ", spans=[" + spans_str + "], turn=" + std::to_string(turn_num)
            + ", keeping full context as fallback";
        SRV_WRN("%s\n", warn_msg.c_str());
        // Also write to dedicated log file
        static std::mutex log_mutex;
        std::lock_guard<std::mutex> lock(log_mutex);
        FILE * flog = fopen("keep_roles_error.log", "a");
        if (flog) {
            fprintf(flog, "[%s] %s\n", common_current_time_string().c_str(), warn_msg.c_str());
            fclose(flog);
        }
        // Fallback: keep full context (n_ctx - 4) so behavior is safe but failure is visible
        n_keep = std::min(slot.n_ctx - 4, slot.task->n_tokens());
    }
} else {
    n_keep = slot.task->params.n_keep < 0 ? slot.task->n_tokens() : slot.task->params.n_keep;
}

The existing add_bos_token adjustment and std::min(slot.n_ctx - 4, n_keep) clamping remain in place after this.

Behavior summary:
- --keep-roles specified + spans found: pin through end of last matching span
- --keep-roles specified + no spans found: loud warning to both normal log + keep_roles_error.log, fallback to full-context keep
- --keep-roles not specified: use --keep value as before (existing behavior)

ROLE DESCRIPTIONS IN SYSTEM PROMPT (OPTIONAL)

Since the system prompt is set once at model load time and never changes, the KV cache for it is built once and never invalidated. This means we can describe the custom roles in the system prompt with no cache cost -- as long as it's part of the initial static prompt, not appended dynamically each turn.

The model already handles all custom roles correctly from the self-describing content alone (proven in production), but adding explicit descriptions makes their purpose unmistakable:

Available context sections appear in labeled role blocks:
  <|turn>datetime  -- current date and time
  <|turn>identity  -- core identity, personality, relationship context
  <|turn>summary   -- conversation summary for long chats
  <|turn>reminders -- active reminders with due dates
  <|turn>memories  -- relevant stored memories about the user

This is optional and does not affect any of the implementation changes. The existing roles already work without it, and datetime follows the same pattern.

KV CACHE BEHAVIOR AFTER CHANGES

- System + identity: Pinned during context shift (n_keep = end of last identity span)
- datetime: Changes every turn (~30 tokens diff). LCP matches everything before and after. --cache-reuse 256 chunk matching reuses identity, summary, reminders, memories, conversation tokens.
- Summary, reminders, memories: Stable between turns, fully cache-reusable.
- System prompt: Never modified -- full KV cache hit.
- --keep flag: No longer needed. Remove from the llama-server launch command.
